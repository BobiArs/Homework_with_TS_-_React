# Домашнє завдання з React: Тестування (Vitest + RTL + Playwright)

## Завдання: Тестування інтерактивного лічильника

У цьому завданні вам потрібно покрити тестами додаток **"Інтерактивний лічильник"**, який ви створили у рамках домашнього завдання до 3-го уроку. Тестування має бути реалізоване на трьох рівнях: **Unit**, **Integration** та **E2E**.

---

## Вимоги до тестування:

### 1. Налаштування середовища (Config)

- Налаштуйте у вашому проекті лічильника Vitest, React Testing Library, JSDOM та Playwright.
- Додайте відповідні команди для запуску тестів у `package.json` (`test`, `test:run`, `test:e2e`).
- Переконайтеся, що конфігураційні файли (`vite.config.ts`, `tsconfig.app.json` та `playwright.config.ts`) налаштовані правильно.

---

### 2. Рівень 1: Unit-тести (Модульне тестування)

Якщо ви винесли бізнес-логіку керування лічильником та історією у кастомний хук (наприклад, `useCounter`), напишіть тести для нього за допомогою `renderHook` та `act` з Vitest.

Якщо кастомного хука немає, напишіть модульні тести для окремого компонента історії лічильника (наприклад, `CounterHistory` або `HistoryLog`) або чистої допоміжної логіки:

- Перевірити, що список історії правильно рендерить переданий масив значень.
- Перевірити, що якщо історія порожня, відображається відповідне повідомлення (або список не рендериться).
- Перевірити відображення не більше 5 елементів історії.

---

### 3. Рівень 2: Integration-тести (Інтеграційне тестування)

Напишіть інтеграційні тести для вашого головного компонента лічильника (`Counter` або `App`) за допомогою **React Testing Library** та **Vitest**:

- **Початковий стан**: перевірте, що початкове значення лічильника дорівнює `0`, а кнопки "+", "-" та "Скинути" відображаються на екрані.
- **Збільшення та зменшення**: перевірте, що клік на кнопку "+" збільшує лічильник на `1`, а клік на "-" зменшує на `1`.
- **Логіка історії**:
  - Перевірте, що при зміні значення лічильника його попередній стан додається в історію.
  - Перевірте, що історія містить максимум останні `5` значень (при спробі додати 6-те значення, найстаріше має видалятися).
- **Кнопка скидання (Reset)**: перевірте, що при кліку на "Скинути" значення лічильника повертається до `0`, а історія очищується.
- **Перемикач кольорів/теми** (якщо реалізовано): перевірте, що при кліку на кнопку перемикання кольору до елемента лічильника додається відповідний CSS-клас або змінюється стиль.

> [!IMPORTANT]
> Використовуйте сучасний `@testing-library/user-event` для симуляції кліків користувача та дотримуйтесь пріоритету запитів (перш за все шукайте елементи через `screen.getByRole`).

---

---

## Критерії оцінювання:

- **Налаштування**: Тести запускаються без помилок конфігурації.
- **Якість тестів**: Використовуються правильні селектори (`getByRole`, `getByText` тощо), відсутнє пряме тестування внутрішнього стейту (тести фокусуються на DOM).
- **Очищення стану**: Тести ізольовані один від одного (скидання стану/інтерфейсу в `afterEach`).
