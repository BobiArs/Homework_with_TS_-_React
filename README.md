# Домашнє завдання: Мережеві запити за допомогою Fetch API 🌐

**Тема:** Робота з вбудованим Fetch API, обробка форм за допомогою `react-hook-form`, уникнення Race Conditions через `AbortController` та створення кастомної обгортки.

**Сервер для запитів (REST API):** [JSONPlaceholder](https://jsonplaceholder.typicode.com/)

- Базовий URL: `https://jsonplaceholder.typicode.com`
- Кінцеві точки (endpoints):
  - Отримання постів: `GET /posts` (додайте ліміт `?_limit=10` для зручності)
  - Отримання конкретного поста: `GET /posts/:id`
  - Отримання користувача (автора): `GET /users/:id`

---

## 🎯 Мета завдання

Створити односторінковий додаток **"Панель керування блогом"** (Blog Dashboard), який дозволяє завантажувати список постів, переглядати деталі конкретного поста разом з даними автора, створювати нові пости через форму та видаляти існуючі. Усі запити мають бути реалізовані за допомогою **Fetch API**.

---

## 📋 Технічні вимоги та кроки виконання

### Крок 1. Підготовка проекту та інтерфейсу

1. Створіть новий React-проект або скористайтеся чистим шаблоном.
2. Розділіть сторінку на дві основні зони:
   - **Ліва колонка**: Список постів (з кнопкою "Завантажити" та індикатором завантаження) + Форма створення нового поста зверху.
   - **Права колонка**: Детальна інформація про обраний пост та його автора.

---

### Крок 2. Завантаження списку постів (GET-запит)

1. Створіть функцію `loadPosts()`, яка робить `GET` запит до `https://jsonplaceholder.typicode.com/posts?_limit=10`.
2. **Обов'язкові правила**:
   - Обробіть перший проміс (отримання відповіді `Response`).
   - Перевірте успішність статусу за допомогою **`response.ok`**. Якщо статус не в діапазоні 200–299, викиньте виняток `throw new Error(...)`.
   - Зчитайте потік тіла відповіді асинхронно за допомогою `response.json()`.
   - Запишіть отримані пости у стейт `posts`.
3. Додайте стан завантаження (`loading`) та відображайте текстовий індикатор ("Завантаження постів...") під час очікування відповіді.

---

### Крок 3. Створення нового поста (POST-запит + React Hook Form)

1. Реалізуйте форму створення поста за допомогою бібліотеки `react-hook-form`.
2. Поля форми:
   - **Title (Назва)** — текстове поле (обов'язкове).
   - **Body (Текст поста)** — текстова область (textarea, обов'язкове).
3. При сабміті форми робіть `POST` запит на `https://jsonplaceholder.typicode.com/posts` з налаштуваннями:
   - `method: "POST"`
   - Заголовки: `"Content-Type": "application/json"`
   - Тіло запиту: серіалізований об'єкт форми через `JSON.stringify(...)`.
4. Після успішного створення (перевірка `response.ok`):
   - Очистіть поля форми за допомогою методу `reset()`.
   - Відобразіть повідомлення про успіх (наприклад: _"Успішно створено пост з ID: [отриманий від сервера ID]"_).
   - Додайте створений пост на початок списку у вашому локальному стейті React, щоб користувач одразу його побачив.

---

### Крок 4. Деталі поста та автора з AbortController (Race Conditions)

1. При кліку на будь-який пост у списку записуйте його ID у стейт `selectedPostId`.
2. Створіть `useEffect`, який реагуватиме на зміну `selectedPostId` та завантажуватиме детальну інформацію про пост (`GET /posts/:id`).
3. **Захист від стану перегонів (Race Conditions)**:
   - Всередині ефекту ініціалізуйте новий контролер: `const controller = new AbortController();`.
   - Передайте `controller.signal` у конфіг запиту `fetch`.
   - Поверніть cleanup-функцію з ефекту, яка викликає `controller.abort()`, щоб скасувати попередній незавершений запит, якщо користувач швидко перемикає пости.
   - Обробіть помилку скасування запиту у блоці `catch`: ігноруйте `AbortError` (`error.name === "AbortError"`), а інші помилки виводьте в консоль.
4. **Запит даних автора**:
   - Отримавши дані поста, візьміть поле `userId` та зробіть додатковий запит `GET /users/:userId` для отримання імені автора та його email.
   - Відобразіть у правій колонці назву поста, його текст, а також блок автора: _"Автор: [Ім'я] (Email: [пошта])"_.
