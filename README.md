# Домашнє завдання: Інтеграція TanStack Query v5 (React Query) 🌐🚀

**Тема:** Перенесення мережевого стану додатка "Панель керування блогом" з локального React-стейту (`useState`, `useEffect`) на **TanStack Query v5**, налаштування клієнта, кешування та мутацій.

Це домашнє завдання є логічним продовженням попередньої роботи з Axios. Ваша мета — відмовитися від ручного керування асинхронними станами, завантажувачами, помилками та `AbortController` на користь автоматизованого серверного стану з коробки.

---

## 🎯 Мета завдання

Рефакторити додаток **"Панель керування блогом"** (Blog Dashboard):

1. Інтегрувати глобальний клієнт `QueryClient` та панель розробника `ReactQueryDevtools`.
2. Замінити ручні виклики `useEffect` / `useState` для завантаження списку постів та деталей на хук `useQuery`.
3. Реалізувати залежні запити (Dependent Queries) для завантаження профілю автора поста.
4. Замінити операції додавання, видалення та редагування на хук `useMutation` з інвалідацією кешу.

---

## 📋 Технічні вимоги та кроки виконання

### Крок 1. Конфігурація провайдера та DevTools (`src/main.tsx`)

1. Встановіть необхідні залежності:
   ```bash
   npm install @tanstack/react-query
   npm install -D @tanstack/react-query-devtools
   ```
2. У файлі `src/main.tsx` створіть екземпляр `QueryClient` із базовими налаштуваннями:
   - `staleTime` — 1 хвилина (`1000 * 60`).
   - `gcTime` — 5 хвилин (`1000 * 60 * 5`).
   - `retry` — 1 спроба при помилці.
3. Огорніть компонент `<App />` у `<QueryClientProvider client={queryClient}>`.
4. Підключіть компонент `<ReactQueryDevtools initialIsOpen={false} />` перед закриваючим тегом провайдера.

---

### Крок 2. Отримання даних за допомогою `useQuery`

1. **Список постів**:
   - У компоненті списку постів видаліть стани `isLoading`, `error` та локальний `useEffect`.
   - Використовуйте `useQuery` для виклику `getPosts()`. Передайте ключ `["posts"]`.
   - Використовуйте прапорці `isPending` та `isError` для відображення інтерфейсу завантаження та помилки.
   - Додайте візуальний індикатор фонового оновлення (`isFetching`), що з'являється у кутку екрану, коли дані оновлюються у фоні.
2. **Деталі поста та Автор (Залежні запити)**:
   - При кліку на пост завантажуйте його деталі за допомогою `useQuery` та ключа `["post", id]`.
   - Завантажуйте деталі автора (користувача), який написав цей пост, використовуючи ключ `["user", post.userId]`.
   - Запит на автора повинен мати параметр **`enabled: !!post?.userId`**, щоб виконуватися тільки після того, як інформація про пост завантажилась.
   - *Зверніть увагу:* вам більше не потрібно вручну створювати `AbortController` та перевіряти `axios.isCancel(error)`. TanStack Query самостійно скасує попередні запити при зміні `id` чи відмонтуванні компонента!

---

### Крок 3. Зміна даних за допомогою `useMutation`

Реалізуйте додавання, видалення та оновлення постів за допомогою мутацій:

1. **Додавання нового поста**:
   - Переведіть форму створення поста на роботу з хуком `useMutation`, передавши функцію `createPost`.
   - У разі успішного запиту (`onSuccess`) виконайте інвалідацію кешу списку постів:
     ```typescript
     queryClient.invalidateQueries({ queryKey: ["posts"] })
     ```
2. **Видалення поста**:
   - Переведіть кнопку видалення поста на хук `useMutation`, що визиває `deletePost`.
   - При успішному видаленні автоматично інвалідуйте список постів з ключем `["posts"]`, щоб інтерфейс оновився.
3. **Редагування поста**:
   - Переведіть форму редагування поста на роботу з хуком `useMutation`, передавши функцію `updatePost`.
   - При успішному редагуванні інвалідуйте деталі поточного поста `["post", id]` та список постів `["posts"]`, щоб вони автоматично оновилися на екрані.

## 🏆 Критерії оцінювання (100 балів)

1. **Глобальне налаштування провайдера та DevTools (20 б.)**: Налаштовано базові параметри `staleTime`, `gcTime`, `retry`. Підключено `ReactQueryDevtools`.
2. **Рефакторинг на useQuery та Залежні запити (40 б.)**: Список та деталі переведені на `useQuery`. Запит автора залежить від результатів запиту деталей поста (`enabled`). Реалізовано стани завантаження, помилки та фонового оновлення (`isFetching`).
3. **Використання useMutation та Інвалідація (40 б.)**: Створення, видалення та редагування постів повністю переведені на `useMutation` з правильним викликом `invalidateQueries` на успішне виконання операцій.
