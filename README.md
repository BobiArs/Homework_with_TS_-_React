# Завдання: Стилізація компонентів у React за топомогою Tailwind CSS

## Мета завдання
Навчитися переносити готову верстку з чистого HTML/CSS у React-компоненти та застосовувати сучасні підходи до стилізації. 

> [!IMPORTANT]
> **Увага:** Логіку роботи додатка (додавання задач, видалення, перемикання стану виконано тощо) реалізовувати **не потрібно**. Ваше головне завдання — розділити інтерфейс на компоненти та стилізувати їх. Для демонстрації інтерфейсу використовуйте статичні тестові дані (Mock Data).

---

## Варіанти стилізації (виберіть один на вибір)
Вам необхідно стилізувати додаток, обравши один із трьох підходів:
1. **CSS Modules** (файли `.module.css` для кожного компонента).
2. **CSS-in-JS** (наприклад, бібліотека `styled-components`).
3. **Tailwind CSS** (утилітарні класи безпосередньо в JSX-розмітці). - обраний цей

---

## Технічні вимоги

### 1. Розподіл на компоненти
Створіть чисту структуру компонентів у вашому React-проекті:
- `<App />` — головний контейнер додатка.
- `<TitleGame />` або `<Header />` — заголовок додатка.
- `<TaskForm />` — форма з інпутом, вибором дедлайну, вибором пріоритету та кнопками дій.
- `<Counter />` — панель статистики (загальна кількість та кількість виконаних задач).
- `<TodoList />` — контейнер для списку завдань.
- `<TodoItem />` — окрема картка завдання.

### 2. Тестові дані (Mock Data)
Для демонстрації стилізації всіх можливих станів завдань, створіть у компоненті `App` масив об'єктів та відрендерить його. Приклад даних:

```typescript
const mockTodos = [
  {
    id: "1",
    text: "Прибрати в кімнаті",
    completed: false,
    priority: "low",
    date: "2026-06-20T12:00"
  },
  {
    id: "2",
    text: "Підготуватися до лекції з React",
    completed: false,
    priority: "high",
    date: "2026-06-16T18:00" // Прострочена задача
  },
  {
    id: "3",
    text: "Здати домашнє завдання №4",
    completed: true,
    priority: "normal",
    date: "2026-06-15T15:00"
  }
];
```

### 3. Стилізація станів задач
Особливу увагу приділіть візуальному відображенню різних станів у компоненті `<TodoItem />`:
- **Пріоритети**: Картка повинна мати різне забарвлення або ліву рамку відповідно до пріоритету:
  - Низький пріоритет (`low`) — зелений колір/бордер.
  - Нормальний пріоритет (`normal`) — жовтий колір/бордер.
  - Високий пріоритет (`high`) — червоний колір/бордер.
- **Виконаний статус**: Текст виконаної задачі має бути закресленим, а сама картка — напівпрозорою (`opacity: 0.6`).
- **Прострочений статус**: Якщо дата завдання минула (і воно не виконане), картка має бути виділена додатковою червоною рамкою чи тінню.

---

## Критерії оцінювання
- **Структура**: Додаток успішно розділений на функціональні React-компоненти.
- **Стилізація**: Усі стилі з оригінального макету перенесені за допомогою обраного методу (CSS Modules, CSS-in-JS або Tailwind) без використання глобального CSS для компонентів.
- **Стани**: Коректно відмальовуються пріоритети, виконані завдання та прострочені дедлайни.
- **Чистота коду**: Відсутній зайвий невикористаний код, типи TypeScript визначені вірно (якщо використовується TS).
