# Домашнє завдання: Простий новинний портал з інтеграцією Mock Service Worker (MSW)

## 🎯 Мета завдання
Навчитися налаштовувати локальне перехоплення API-запитів за допомогою **Mock Service Worker (MSW)** у браузері, інтегрувати маршрутизацію (React Router) та реалізувати роботу зі станами завантаження (Loading) та помилок (Error).

---

## 📋 Опис проєкту
Вам необхідно створити простий новинний портал, який складається з двох основних сторінок:
1. **Головна сторінка (`/`)**: Стрічка новин (список карток новин із заголовком, коротким описом, датою та категорією).
2. **Детальна сторінка новини (`/news/:id`)**: Повна картка новини з основним текстом статті, автором, обкладинкою та датою публікації.

Усі дані мають завантажуватися через стандартні HTTP-запити (`fetch` або `axios`), які перехоплюватимуться MSW воркером. Реальний бекенд створювати чи підключати не потрібно.

---

## 🛠️ Технічні вимоги

### 1. Налаштування MSW (Mock API)
* Встановити пакет `msw` як dev-dependency.
* Ініціалізувати сервіс-воркер у папці `public`:
  ```bash
  npx msw init public/ --save
  ```
* Створити файл бази даних `src/mocks/db.ts`, у якому описати TypeScript-інтерфейс новини та підготувати масив початкових новин (**мінімум 5 унікальних новин**).
  * *Поля новини*: `id`, `title` (заголовок), `summary` (короткий опис), `content` (повний текст новини), `category` (категорія, наприклад, Технології, Спорт, Культура), `author` (автор статті), `createdAt` (дата створення), `imageUrl` (посилання на зображення-заглушку, наприклад з Unsplash).
* Створити файл обробників `src/mocks/handlers.ts`, який перехоплюватиме два ендпоінти:
  * `GET /api/news` — повертає список усіх новин (можна без детального поля `content` для економії трафіку). Додати штучну затримку `delay(600)` для симуляції мережі.
  * `GET /api/news/:id` — повертає повну інформацію про конкретну новину за її `id`. Якщо новину з таким ID не знайдено — повертати помилку `404 Not Found`. Також додати затримку `delay(600)`.
* Налаштувати запуск воркера в `src/mocks/browser.ts` та підключити його ініціалізацію у точці входу додатка `src/main.tsx` (запускати MSW тільки в режимі розробки `development`).

### 2. Маршрутизація (React Router)
* Налаштувати роутер за допомогою `createBrowserRouter` або `HashRouter`.
* Забезпечити навігацію між сторінками:
  * Клік на картку новини на Головній сторінці перенаправляє користувача на `/news/:id`.
  * На сторінці деталей новини має бути кнопка «Назад» для повернення до загальної стрічки.

### 3. Компоненти та стани інтерфейсу
* **Головна сторінка**:
  * Відобразити список новин у вигляді сітки (Grid).
  * Кожна картка новини повинна містити: картинку, категорію (як кольоровий бейдж), заголовок, короткий опис, дату публікації та посилання «Читати далі».
  * **Стан завантаження**: поки дані завантажуються, показувати лоадер або Skeleton-картки.
* **Детальна сторінка новини**:
  * Відобразити детальну інформацію про новину: велике зображення-обкладинку, категорію, дату, автора, заголовок та повний текст (розділений на абзаци).
  * **Стан завантаження**: показувати лоадер під час запиту.
  * **Стан 404**: якщо новину за вказаним ID в URL не знайдено, показати користувачеві інформативне повідомлення про те, що новини не існує, та кнопку повернення на головну.

## 📂 Рекомендована структура папок (спрощена)
```text
src/
├── components/          # Спільні компоненти (Header, NewsCard, Spinner)
├── pages/
│   ├── NewsListPage.tsx # Головна сторінка (стрічка новин)
│   └── NewsDetailPage.tsx # Сторінка деталей новини
├── mocks/
│   ├── db.ts            # Ініціалізація новин в пам'яті
│   ├── handlers.ts      # MSW хендлери (GET /api/news, GET /api/news/:id)
│   └── browser.ts       # Налаштування setupWorker
├── App.tsx              # Конфігурація роутера
├── main.tsx             # Точка входу (запуск MSW + рендер React)
└── index.css            # Стилізація
```

## 📈 Критерії оцінювання
1. **Правильність налаштування MSW (40 балів)**: воркер успішно реєструється в браузері, перехоплює запити, у вкладці Network в консолі розробника видно реальні запити до `/api/news` та `/api/news/:id`.
2. **Реалізація сторінок та навігації (30 балів)**: переходи між головною сторінкою та деталями новини працюють коректно за допомогою лінків роутера без перезавантаження вкладки.
3. **Обробка станів інтерфейсу (20 балів)**: наявні та коректно відпрацьовують стани завантаження (Loading spinner/skeleton) та стан помилки / 404 (якщо новину не знайдено).
4. **Якість коду та стилізація (10 балів)**: охайний та структурований код, привабливий адаптивний інтерфейс (можна використовувати Tailwind CSS або чистий CSS).
